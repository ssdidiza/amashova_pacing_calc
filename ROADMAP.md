# Roadmap & status tracker

The handoff document between working sessions. **Update this file at the end
of every session:** move items between sections, date the entry, note new
caveats. Last updated: **2026-07-20**.

## Vision

Evolve from an Amashova-specific calculator into the go-to free race pacing
platform for South African road cycling events: pick a race, set a target,
get checkpoint ETAs, a fuel plan, and race-ready printouts — then bring your
plan back after the race and compare.

## Done

### v2.0 — Race-ready print system (2026-07-19, commit d022216)
- Three print formats from a print-preview dialog: stem card (90×60 mm, with
  spare copy), top tube strip (220×40 mm, rotated onto A4), full race plan
  (A4 ×2: inputs, pacing table, elevation profile, fuel/hydration schedule,
  segment cues, rider notes).
- Fuel strategy engine (carb target → gel schedule mapped to time/clock/km,
  drink reminders, optional hourly sodium), custom rider notes on every
  format, `?print=` deep links, PDF-friendly document titles.
- Sample PDFs + desktop/mobile screenshots in `samples/`.

### v2.1 — Multi-race platform + Ride Joburg 2026 (2026-07-20, commit 439ba6e)
- Race registry (`races/*.js` on `window.RACES`), hero race picker, `?race=`
  in share links and saved settings. Amashova remains default.
- `tools/gpx-to-config.js`: GPX + manifest → full race config (distances,
  smoothed elevation via open-elevation.com with cache, gradient-derived
  pacing factors, conservative/aggressive ramps).
- Ride Joburg 97 (2026) config from official GPX: 8 official water points as
  checkpoints, climbs (Douglasdale drag, Jan Smuts steps, KOM · Westcliff,
  Nasrec rises, Woodmead sting), ±877 m smoothed climbing, per-segment cues.
- Template upgrades: dense stem card (>7 checkpoints), compact long fuel
  tables, elevation axis scaled to route min/max, climbing total in header.

## Known caveats

- Settings (target time, notes) are one shared localStorage object, not
  per-race — switching races keeps the same target time.
- Fuel table can crowd page 2 of the full plan for very long rides (8 h at
  90 g/h); `is-long` compact mode mitigates but doesn't paginate.
- `?print=` param is captured at script parse time because the app rewrites
  the URL — don't "simplify" that away (see AGENTS.md).

## Messaging rules

- Ride Joburg 2026: "all-new route, new start and finish at Kyalami — old
  splits don't apply". Never "reversed"/"flipped".
- All guidance carries the "estimate, not guarantee" disclaimer.
